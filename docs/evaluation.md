# 评估方法

RAG 系统要「有数据支撑」，而不是「看起来能用」。评估分两层。

## 1. 检索层：命中率

- **命中率@k**：对每条测试问题，判断检索返回的 top-k 里是否包含「标准答案所在的那块」。
- 已实现：`app/eval/metrics.py` 的 `retrieval_hit_rate`。
- 需要构建一个测试集：若干 `(问题, 标准 chunk id)` 对。

## 2. 生成层：忠实度

- **忠实度**：回答里的每个陈述，是否都能被检索到的上下文支持（防止幻觉）。
- 实现思路（P4）：用 LLM 逐句判断「该句是否被 context 支持」，取支持比例。
- 代码位置：`app/eval/metrics.py` 的 `answer_faithfulness`（待实现）。
